# Scruter CMP for apps — conformance kit

The protocol of the CMP module of the SDKs (`ScruterCMP`, `net.scruter:scruter-cmp`, the React Native and Flutter
wrappers): `docs/CMP-MOBILE.md` in the Scruter monorepo is the normative behaviour, `docs/API.md` §5.1 the HTTP shapes.
The backend, the site script and every SDK test against what is here.

## Schemas (`../schema/cmp-*.schema.json`, JSON Schema 2020-12)

| Schema | Body |
|---|---|
| `cmp-config` | the answer of `GET /m/v1/cmp?a=<app id>&p=<ios\|android>&av=<app version>&sv=<sdk version>` |
| `cmp-hit` | `POST /cmp/hit` from an app: one per opening (a cold start, or a return after 30 minutes in the background) |
| `cmp-consent` | `POST /cmp/consent` from an app: one per decision |
| `cmp-sdks` | `POST /m/v1/cmp/sdks`: the third-party SDKs an app version links, once per (app version, catalogue version) |
| `cmp-sdk-catalogue` | the answer of `GET /m/v1/cmp/sdks/{version}.json`: the classes to look for |

The beacons' schemas are strict (what a conforming SDK sends); the server is lenient (it ignores unknown keys). Validate
a recorded body with `node ../validate.mjs cmp-consent body.json`.

## Golden bodies (`bodies/`)

One example of each message, valid against its schema: `config.json` (an app with a published banner, Consent Mode,
a photo header and its store icon), `config-tcf.json` (the same app with the IAB TCF on, §6), `config-off.json` (`on: 0`: unknown app, no published banner, CMP removed or
suspended — show nothing, grant nothing, ask again after `ttl`), `hit.json`, `hit-debug.json` (a debug build of the
variant B of an A/B test, on a tablet), `consent.json`, `consent-android-back.json` (Android's back action: `close`,
a refusal), `sdks.json`.

Fields worth knowing:

- `w` is the **shorter side** of the screen in points (iOS) or dp (Android): under 600 a phone, from 600 a tablet.
- `cv` names the SDK that sends: `ios/1.1.0`, `android/1.1.0`, `react_native/1.1.0`, `flutter/1.1.0`.
- `ap` is the identifier the app runs as (`Bundle.main.bundleIdentifier`, `context.packageName`): it must be one of the
  configuration's `app.ids`, else the server drops the beacon.
- `h` is the configuration's `ui.text_hashes[l]` (or the `hash` of `GET /cmp/{code}/texts-{banner id}-{lang}.json` for a
  language fetched apart): the SDK never computes it.
- `dbg: 1` from a debug build: its openings count nowhere, its proofs stay out of the registry and show 24 hours in the
  console's live check.
- `m`, the Consent Mode signals sent as granted, follow `vectors/consent-mode.json` (`security_storage` included).

## Vectors (`vectors/`)

- `stored-value.json` — the stored choice, format 1 (the cookie `scruter_consent` on the web; in an app, the same value
  in its own storage: `UserDefaults(suiteName: "net.scruter.cmp")`, Android `SharedPreferences` `net.scruter.cmp`):
  values that parse (with the result, and back), values that do not.
- `reask.json` — when the banner asks again (docs/CMP.md §4.4, rules 1 to 4): configuration, stored choice, now → ask.
- `consent-mode.json` — the Google Consent Mode signals of a choice.

The site script runs the same vectors (`cmp/test/conformance.test.ts`), so the web and the apps behave alike.

## IAB TCF (`tcf-vectors.json`, `tcf/`)

When the site's TCF settings are on, the configuration's `config.tcf` (`bodies/config-tcf.json`) names the CMP id (528),
the GVL version, the selected vendors, the legal basis of each IAB purpose, the special features allowed, the IAB
purposes grouped under each banner purpose (`stacks`), the publisher's country, the vendor subset
(`vendors_url`, relative to `config.endpoint`) and the IAB translations (`translations_url`, `{lang}` replaced by the
banner's language, lower case; a missing translation falls back to the vendor list's English).

- `tcf-vectors.json` — generated by `node tcf-vectors.mjs` from the site script's own TCF code (`cmp/src/tcf/model.ts`
  and `tcstring.ts` in the Scruter monorepo; `--check` fails when it is out of date). `cases`: the settings, the vendor
  list, the banner's language, the banner purposes granted and the visitor's TCF choice (`choice`: `null` when the
  visitor did not open the TCF parts, else per vendor consent and legitimate interest, per IAB purpose on legitimate
  interest, per special feature, and per IAB purpose on consent the visitor set; absent entries follow the banner
  purposes) → the TC model (`model`, the fields of the core string, the disclosed vendors and the publisher TC segment),
  the TC string (`tc`, base64url, each segment padded to 24 bits) and the in-app keys (`keys`). `reask`: a stored string
  and the current settings → ask again (docs/CMP.md §4.4 rule 5: no or an unreadable string, another CMP id or TCF
  policy, or a selected vendor of the vendor list the string did not disclose; rules 1–4 are `vectors/reask.json`'s).
  The dates are `now`'s day (`created` = `last updated`).
- `tcf/vendors-186.json` — a vendor subset as `GET /cmp/{code}/vendors-{gvl}.json` serves it: the IAB TCF test page's ten
  vendors of GVL 186 and every stack, plus vendor 1500 as the GVL keeps a deleted one. `tcf/186-fr.json`,
  `tcf/186-de.json` — IAB's French and German translations as `GET /cmp/tcf/{gvl}/{lang}.json` serves them. The vendor
subset carries six of Google's other ad tech providers (`acProviders`), which the golden configuration selects.

The in-app keys (IAB Tech Lab, CMP API v2.2, « In-App Details »), in `UserDefaults.standard` (iOS) and the default
`SharedPreferences` (Android), written before the sheet closes and at every later change, removed by `debugReset()` and
when the site turns the TCF off: numbers as integers (`IABTCF_CmpSdkID` 528, `IABTCF_CmpSdkVersion`,
`IABTCF_PolicyVersion`, `IABTCF_gdprApplies` 1 for everyone, `IABTCF_PurposeOneTreatment` 0,
`IABTCF_UseNonStandardTexts` 0), strings for the others. Binary strings carry `1` at index n for the id n + 1: purposes
and the publisher's purposes on 11 characters, special features on 2, vendors up to the highest id set (empty when
none), the publisher's custom purposes empty (none). `IABTCF_PublisherRestrictions{purpose}` exists for each purpose
with a restriction: the restriction type (`0` not allowed, `1` require consent, `2` require legitimate interest) of
vendor n + 1 at index n, `_` for a vendor without one; the keys of purposes 1–11 without a restriction are removed.
`IABTCF_CmpSdkID`, `IABTCF_CmpSdkVersion`, `IABTCF_PolicyVersion`, `IABTCF_gdprApplies` and `IABTCF_PublisherCC` are
also written as soon as a configuration with the TCF arrives, before any choice, so that vendors know a CMP is there.

Google's Additional Consent string v2 (`IABTCF_AddtlConsent`, Google's « Additional Consent technical specification »)
is written with the TC string for a site with Google's other ad tech providers (`config.tcf.ac_providers`; their names
and privacy policies in the vendor subset's `acProviders`): `2~<consented ids>~dv.<ids only disclosed>`, ids ascending.
Every selected provider found in the vendor subset is disclosed; one is consented when IAB purposes 1, 3 and 4 are and
the visitor did not switch it off (untouched, its switch follows those purposes). The key is removed with the
decision's and is absent for a site without providers. The proof's `tc` carries the TC string, then `~` and the
Additional Consent string. A stored string that does not name a provider of the vendor subset asks again, as for
vendors (the vectors' `stored_ac`).

## Words (`words/<lang>.json`)

The few words of the sheet that are not the banner's own texts (« Étape {n} sur {t} », « Suivant », « Certifié par »,
« Toujours actif », the confirmation « Vos choix ont été enregistrés. » and its second line `savedHint`, the consent id's « Copier »…), in the 33
languages a banner speaks. They are the site script's words (`cmp/src/ui/i18n/<lang>.json`, the same translations and
register), with `state` worded for an app (« Vos choix dans cette app »). The IAB TCF layers' words are the site
script's `tcf*` ones (`tcfShort`, `tcfTitle`, `liIntro`…), with `tcfScope`, `tcfPrefsIntro` and `tcfStorage` worded
for an app and `tcfSearch` added. The SDKs embed them; `{n}`, `{t}` are
placeholders. A new word goes into the 33 files at once.

## Checks

```sh
node check.mjs        # every golden body against its schema, what the schemas must refuse, the SDK catalogue, the words,
                      # the TCF vectors' shape
node tcf-vectors.mjs --check   # in the Scruter monorepo: the TCF vectors are those of the site script's code
```

The backend's tests (`scruter-ingest`, `cmp_app_e2e`) post the same shapes to a real ingest and compare the keys of its
`GET /m/v1/cmp` answer with `bodies/config.json`; a change of the protocol edits the schema, the bodies, the vectors,
`docs/API.md` §5.1 and the server in the same commit.
